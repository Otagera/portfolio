## Module 1: Key-Value Engine (Strata KV)

<details open>
<summary><span class="status status-active">in progress</span> 1.1 Foundations done: MemTable + naive on-disk persistence, 15 tests passing. Next: SSTables (1.2).</summary>

Phases below match the actual build order from `strata_ts`'s git history, not a topic list — each phase is a real commit boundary, small enough to finish and devlog in one sitting. In the TS version, MemTable, SSTables, and compaction aren't split into separate files — they're all methods on one `StrataKV` class in `kv/engine.ts`.

<div class="decision">
<strong>Design decision (carried over from the pre-wipe Rust attempt, confirmed 2026-08-15):</strong> storage uses raw binary encoding (`Vec&lt;u8&gt;` keys/values throughout), <em>not</em> JSON like the TS WAL (`WALManager` is JSON Lines, one object per line). Deliberate divergence from the TS reference — keep it in mind for WAL and SSTable serialization too, not just the MemTable.
</div>

<div class="decision">
<strong>Design decision (2026-08-19):</strong> deletes are tombstones modeled as `Option&lt;Vec&lt;u8&gt;&gt;` values in the map (`BTreeMap&lt;Vec&lt;u8&gt;, Option&lt;Vec&lt;u8&gt;&gt;&gt;`), not a sentinel string like TS's `$nullified`. `get` returns `Option&lt;Option&lt;Vec&lt;u8&gt;&gt;&gt;` — outer `None` means "key not in this layer, keep searching," `Some(None)` means "tombstoned, stop here," `Some(Some(v))` means "live value." This three-state shape is what lets a future multi-layer read (MemTable → older memtables → SSTables) stop at a tombstone instead of falling through to a stale value in an older layer. `insert` mirrors the same shape in its return value (the previous entry, if any), and tracks `size` incrementally rather than the TS reference's entry-count threshold.
</div>

<div class="decision">
<strong>Design decision (2026-09-01):</strong> naive on-disk persistence uses a length-prefixed binary record format instead of TS's delimited text format (`the_humble_file.txt`, sentinel-string tombstones): `key_len:u32 | key | tag:u8 (0=tombstone, 1=value present) | value_len:u32 (if tag==1) | value (if tag==1)`. Persistence lives in a new `Engine` struct that wraps `MemTable` (kept as a pure in-memory type with no knowledge of files) alongside an open file handle — `Engine::open` reads the file and replays it into a fresh `MemTable`, and `insert`/`delete` write the encoded record to disk <em>before</em> updating the in-memory copy, so a failed write never leaves memory and disk out of sync. Code is split across `strata-rs/src/mem_table.rs` and `strata-rs/src/engine.rs` (`main.rs` is now just the crate entry point).
</div>

### 1.1 Foundations
- [x] MemTable (in-memory sorted map) — `BTreeMap<Vec<u8>, Option<Vec<u8>>>` (see tombstone design decision above); TS reference: `src/kv/engine.ts` (`StrataKV`, in-memory map + get/set, though TS uses string keys/values and a sentinel-string tombstone instead of `Option`) — `insert`, `get`, `delete`, `size`, `clear` implemented and tested (`strata-rs/src/mem_table.rs`)
- [x] Naive on-disk persistence + first tests — `Engine` struct wrapping `MemTable` + an open file handle; binary length-prefixed record format, replay-from-file on startup (see design decision above); TS reference: `index.ts`'s original `database_init`/`database_set`/`database_get`/`database_delete` prototype (single append-only text file + in-memory offset map) — `open`, `insert`, `get`, `delete`, `size`, `clear` implemented and tested (`strata-rs/src/engine.rs`)

### 1.2 LSM-Tree Core
- [ ] SSTables (immutable on-disk files) — write side in `src/kv/engine.ts` (flush logic), read side in `src/kv/sst_iterator.ts` (`SSTIterator`)
- [ ] Bloom filters — `src/shared/bloom_filter.ts` (`BloomFilter`)
- [ ] Sparse indexing — first pass (block offsets, min/max key ranges) — `src/kv/engine.ts` (block index build), type in `src/shared/interfaces.ts` (`BlockIndex`)

### 1.3 Compaction
- [ ] K-way merge compaction — `src/kv/merge_iterator.ts` (`KWayMergeIterator`), triggered from `src/kv/engine.ts`
- [ ] Automatic triggering / background compaction loop — `src/kv/engine.ts`

### 1.4 Durability
- [ ] Write-Ahead Log (WAL) — `src/kv/wal.ts` (`WALManager`), perf-tested in `src/kv/wal_perf.test.ts` — previously reached this point (Feb 2026) before the code was lost
- [ ] Recovery from WAL on startup — `src/kv/wal.ts` + recovery call in `src/kv/engine.ts` constructor

### 1.5 Read Path
- [ ] K-way merge iterator (range scans) — `src/kv/merge_iterator.ts`
- [ ] Scan support — `src/kv/engine.ts` (`scan()`), `src/kv/scan.test.ts`
- [ ] Sparse indexing, refined (block-level, revisited after WAL in the TS build) — `src/kv/sst_iterator.ts`, `src/kv/mem_table_iterator.ts` (`MemTableIterator`)

## Module 2: Document Engine (Strata Doc)

<summary><span class="status status-todo">not started</span> built as a layer on top of Strata KV.</summary>

- [ ] Transaction manager: ACID via WAL markers + MVCC (snapshot isolation, transaction IDs) — **no TS reference exists for this.** `transaction.ts` only does buffering; grepping the TS codebase turns up no MVCC/snapshot-isolation implementation at all. This is genuinely new ground, not a port — the TS version's own "Strata SQL: Transaction Manager" issue (`u5y`) is still open too.
